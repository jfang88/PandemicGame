# T15 browser regression gate

| Gate | Automated evidence |
| --- | --- |
| U01 | `test:e2e` starts fresh, deterministic 2-, 3- and 4-player matches in independent Chromium contexts. The test drives legal actions through the UI until the Worker reports a terminal outcome. The rendered revision converges in every context after every accepted move. Two extra local fixtures verify a final cure win and a player-deck loss. |
| U02 | `test:e2e` replays an older and duplicate WebSocket snapshot, takes a peer offline during an accepted move, then reloads and verifies convergence. A short-lived ticket forces the Workerd alarm to end the session and the same context reacquires access. `test:connected-smoke` covers a stale command and an expired saved room. |
| U04 | `test:e2e` exercises the 768-pixel Chromium tablet layout, color text, keyboard inspection and submission, discard dialog focus and terminal heading focus. |
| Lobby and hand limit | The 4-player match races two independently signed-in browsers for the last seat and verifies the Worker accepts exactly one. Only the hand owner can submit a discard. The test checks the cards removed, the automatic continuation and the resulting hand. |
| S09 / S10 / U05 | Workerd checks signed Firebase claims, unsigned emulator rejection and certificate cache behavior. `test:auth-smoke` checks simulated popup outcomes, refresh, identity switch and invite return. The web and Worker production artifact scans exclude local identities and fixtures. |

The complete matches use a fixed local seed and a bounded pass-and-discard driver. They measure synchronization and legality. The near-terminal fixtures use only the loopback Worker entry and a fixed scenario for a started room owned by the caller. The browser suite uses local test identities. Live Google and Microsoft sign-in and tablet Safari/WebKit verification remain in T17.
