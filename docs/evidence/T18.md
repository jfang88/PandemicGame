## Independent final review

A review session that did not write T01–T17 read the Worker router and entry points, Firebase verification, the room Durable Object, realtime tickets and sockets, the limiters, the lobby, the local-test entry, the deployment scripts and the workflows. It followed [the review prompt](../../prompts/REVIEW_TASK.md). Its focus was cross-await races, partial commits, retries, hidden-state leaks, JWT checks, cross-room access, deployable bypasses and hibernation recovery. It also used the local rehearsal below and API reads of the repository settings.

| Finding | Severity | Result |
| --- | --- | --- |
| A read or ticket request for an unknown room ID instantiates a room object and writes its schema. No alarm removes it. The local rehearsal measured five new empty objects, each with nine tables, after five reads. | Medium | Known issue K1 with a recommended follow-up. No room data is exposed. |
| `main` is not a protected branch, and the deploy workflow requires one. | Blocking for deployment, owner action | Added to the owner prerequisites. |
| PROTOCOL.md lists `GET /api/rooms/:id/events`, which the Worker does not implement. | Low | The row is now marked not implemented (K6). |
| `scripts/test-local-play.mjs` was not part of CI. | Low | Added to npm scripts and CI. |
| README.md and START_HERE.md described the pre-T01 build kit. | Low | Updated for handoff. |

Checks with no defect found:

- Mutations validate, check the version, deduplicate, and write state, events and receipts in one synchronous SQLite transaction. The transaction contains no awaits.
- Acknowledgment and broadcast wait for `storage.sync()`.
- Retries compare canonical hashes.
- Socket tickets are origin-bound, single-use and consumed in a transaction.
- Firebase verification fixes the certificate URL, requires RS256 and checks the issuer, audience and claims.
- The local identity requires a loopback hostname.
- The normal Worker bundle excludes test entry points.
- Production dispatch checks the canonical repository ID `1436820826` and owner ID `62051186`. Both match the GitHub API.

Not verified here: behavior on the real Cloudflare edge and on Firebase, Safari/WebKit, and engine rules beyond the T06 review.

## Local recovery rehearsal

This rehearsal ran three builds in turn against one persisted Wrangler state directory:

| Build | Commit | Storage version |
| --- | --- | --- |
| Candidate | This branch | 6 |
| Previous | `60b6680` (T16 merge) | 6 |
| Older | `e24d0ea` (T15 merge) | 5 |

Each build used its own pinned dependencies and the loopback test entry. The script drove the HTTP API and retried rate-limited commands with the same envelope.

1. The candidate created a lobby and a two-player game. It passed until a discard was pending at revision 23.
2. The previous build served byte-identical snapshots for both rooms and both members. It accepted the pending discard and a lobby role change.
3. The candidate served those writes unchanged and accepted the next move.
4. The older build answered reads and commands on both rooms with `503 ROOM_INCOMPATIBLE`.
5. The candidate then served exactly the state from step 3 and continued the game.

This covers compatible rollback and roll-forward, and a refused incompatible downgrade. It does not replace the preview rehearsal, which uses Cloudflare versions and real hibernation.
