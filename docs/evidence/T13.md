# T13 connected lobby gate

| Gate | Evidence |
| --- | --- |
| Lobby and play | Chromium used separate browser contexts for two, three and four test identities. Each group created a room, joined through an invite, picked roles, readied, started, and completed a synchronized turn through local Workerd. Nonactive players had no turn action. |
| Refresh and stale actions | Reload retained each seat. A competing server action advanced the revision before submission. The UI reported the conflict and refreshed state without silently resubmitting the move. |
| Worker transport | Workerd integration tests cover a streamed empty WebSocket ticket request and reject a streamed request carrying bytes. |
| Build isolation | Auth and local-play browser smoke tests exercised simulated popup outcomes and local play. The configured production bundle checks exclude the local game fixture and private engine code. |

Run the connected scenario with `npm run test:connected-smoke` after installing Chromium through Playwright. It uses loopback test identities and the Worker room implementation. T17 covers live Firebase provider accounts and the Cloudflare preview deployment.
